REST Endpoints
MethodPathDescription
POST/esign/requestSubmit an eSign request XML (documents + hashes) for signing
POST/esign/statusQuery the status of a previous eSign transaction
GET/esign/transaction/{id}Fetch a stored transaction response by id
POST/esign/auth/callback?txnref=…Authentication completion callback (base64 of txn|responseCode)
POST/ekyc/autheKYC authentication with PIN hash and optional composite second factor
POST/ekyc/auth/second-factorSecond factor verification (SMSOTP / TOTP / MAT / FIDO / PUBSIGN)
POST/ekyc/bank-kycBank KYC submission
POST/ekyc/public-key/registerPublic key registration
GET/esign/dev/users, /pin-hash, /send-otpDev-only helpers backing this console (seed users, compute PIN hash, retrieve OTP)
GET/esign/dev/transactions/{id}Transaction details for auth page (document hashes, status, metadata)
POST/esign/dev/auth-and-signAuthenticates user (PIN+OTP), signs document hashes, returns CMS signature + certificate
GET POST/api/asps (+ PUT/DELETE, stats)ASP registry management API — UI at ASP Management. Defaults seeded at startup.
GET/api/esign-logsAudit trail of every eSign request (sign / status / callback) with filters — UI at Audit Logs
POST/api/certificates/requestForwards certificate-enrollment JSON to the CA endpoint configured in application.yml (ca.*). eSign metadata fields (signerId, aspId, transactionId, docHash, docInfo, signingAlgorithm) are captured in the audit trail but never forwarded to the CA. GET /api/certificates/settings shows the active config.
GET/swagger-ui.htmlInteractive OpenAPI documentation for every REST endpoint — open Swagger UI (raw spec: /v3/api-docs)

ASP (Application Service Provider): submit eSign XML with document hash → upload PDF, compute hash, embed CMS signature.
ESP (eSign Service Provider): redirect user to /auth.html?txn=TXN-ID for PIN+OTP authentication → ESP calls CM for signing → CMS signature returned → ASP embeds into PDF.
